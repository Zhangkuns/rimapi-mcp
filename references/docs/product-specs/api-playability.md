## 交付范围

固定本机原版 RimWorld **1.6.4871 rev600**、Core 与 Royalty、Ideology、Biotech、Anomaly、Odyssey 同时启用。
包括正常新建游戏与载入、基础殖民地经营、地图/世界旅行、五 DLC 正常机制、事件决策、所有本版正常结局，以及失败后原生允许的继续游戏选择。
正常游戏中可由玩家决定、且改变游戏状态的合法选择，均属于本合同；外观、命名和预设可以后置，不能因低优先级自动删除。
API 自身的能力发现、参数/目标发现、鉴权、主线程执行、提交结果与状态读回也必须支持该流程。

一次性运行前提是游戏、五 DLC 与 RIMAPI 已安装并启用、服务地址/凭据已交付、游戏进程可由运行工具启动。
开始游玩后不要求用户补点界面、修改存档、打开开发者模式、准备特殊 fixture，或手填只能从内部内存取得的 ID。
正式 DLL 部署继续遵从用户授权；本次没有部署，不能把源码/文档更新当作正式版本已可游玩。

不承诺任意第三方 Mod、未来版本、1.5、未安装内容和任意 DLC 开关组合。
不创造原版没有的玩家权利：随机结果、自然遗传、自动灵魂绑定等按原生规则发生。
开发者动作继续保留其独立合同；它们不替代正常玩法的资源、研究、资格、工作或结果。
正常玩法、环境工具和调试直接变更的详细边界见[API使用语义](api-usage-semantics.md)；这是行为分类，不改变现有鉴权。
音量、分辨率、百科跳转、摄像机和纯显示开关不要求复制成业务 API；涉及资格判断的数据仍须能查询。

## 每类操作必须闭合的四步

| 环节 | 调用方必须能做到 | 不能充当完成证据的情况 |
| --- | --- | --- |
| 查询 | 找到准确人物/物品/建筑/地图/世界对象、当前值、合法选项、必要材料/费用与阻止原因 | 只有计数/显示名；必须靠 fixture 知道实例 ID；Def 列表冒充运行中实例 |
| 决策 | 用明确参数选择正常玩家可选择的内容，包括数量、参与名单、策略、地点、确认和取消 | 固定默认选项；只支持主理念/地图内分支却声称全部支持 |
| 执行 | API → 游戏主线程 → 对应原生业务方法、策略或完整工作；无须打开窗口 | 返回窗口/坐标后要求人点；任意单 target Job 冒充多目标原生工作；直接修改最终效果代替正常过程 |
| 读回 | 分清接受/排队/执行中/完成/失败；能查真实对象、资源、holder、策略、信号和结果 | HTTP 200/queued/session ended 当作完成；超时后盲重发导致重复副作用 |

窗口源码仅作为查找玩家选择和原生执行逻辑的依据。接口可以直接返回结构化选项并接收选择参数，
不要求先创建 `Dialog_*`、保持某窗口打开、选择屏幕控件或安装 Cua。
已有 API 如需利用原生对象组织业务，须自行完成正常后续与清理，不把窗口处理交给调用方。
不向客户端开放任意反射、代码或菜单委托执行。

可由已有 API 组合完成的功能复用现有实现；组合的目标/参数和读回必须实际可表达。
正常策略可以等待原生 AI 执行；应能查询所需前置与阻塞原因，不要求玩家绕过正常等待或保证随机成功。
“无人工介入”指技术上无需人补操作，不意味着 RIMAPI 自身替调用方作战略决策或保证获胜。

## 核销与范围稳定

1. [账本](five-dlc-remaining-checklist.md)中的 G 实现/修复、V 核验、A 明确待判事项全部有结论；旧限定通过不退回成未实施。
2. [原生候选与路由登记](../references/reviews/2026-11-12-api-playability-surface.json)中的入口必须落到业务行、已有覆盖或有理由的排除。
   候选“有归属”不等于行为已审完；按[全功能计划](../exec-plans/active/five-dlc-full-function.md)的七包完成正常回调/参数/结果映射，保留的语义待核须在交付前清零。
3. 既有路由逐项保留来源与用途；正常游玩所用路由的请求参数、实际实现和合同一致，必要查询不能依赖 UI。
   不把所有 GET、调试或重复/便捷路由各重跑一遍当作业务要求。
4. 完成相关构建、真实原生终态和已知缺陷回归；E-01–10连续流程通过并记录构建/游戏版本/证据身份。
5. 文档交付准确参数与流程，未留“请用户手动操作”作为技术步骤。完成以上条件即可认定**本版本纯 API 游玩交付完成**。

**后来发现本版本范围内遗漏的正常操作，属于本次交付缺陷，应修复；不能再解释成新阶段或临时扩大目标。**
只有用户新增需求、第三方 Mod、版本变化等才作为新范围。不会承诺软件永无未知 bug，
也不会用“可能还有更多”作为长期不结束交付的理由。

第二次复核已推翻“66项就是所有剩余”，本次又修正“60开放族即全部待办”；具体差集和七包来源核对公开列入执行计划。
这是一份可执行的完整交付范围和当前缺口账本，**不是现在已经穷尽证明了每条原生分支的完成声明**。
